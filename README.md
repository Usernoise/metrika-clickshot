# ClickShot Metrika v0.1

## Сервер

```text
https://metrika.clickshot.ru
```

## Каталог проекта

```text
/var/www/metrika.clickshot.ru
```

## Тестовый сайт

```text
neural-courses.ru
```

## Код подключения

Без Slide Cookie:

```html
<script src="https://metrika.clickshot.ru/counter.js?id=neural_courses" async></script>
```

Со включённым Slide Cookie админка покажет тот же URL без `async`. Его нужно
поместить в `<head>` до штатного динамического сниппета Яндекс.Метрики.
Блокируются `.src` и `setAttribute('src', ...)` у скриптов, созданных через
`document.createElement`. Статические `<script src>` Метрики, noscript-пиксели,
iframe и сторонние загрузчики этим перехватом не защищаются: их нужно убрать
или явно запускать после согласия. Порядок тегов сам по себе не защищает такие интеграции.

## Установка

### 1. Установить зависимости

```bash
sudo apt update
sudo apt install -y php8.3-cli php8.3-fpm php8.3-sqlite3 php8.3-mbstring php8.3-curl php8.3-xml unzip
```

### 2. Создать каталог

```bash
sudo mkdir -p /var/www/metrika.clickshot.ru
```

### 3. Распаковать архив

```bash
sudo unzip metrika-clickshot-v0.1.zip -d /tmp/metrika-clickshot
sudo cp -R /tmp/metrika-clickshot/metrika-clickshot-v0.1/. /var/www/metrika.clickshot.ru/
```

### 4. Права

```bash
sudo chown -R root:www-data /var/www/metrika.clickshot.ru
sudo chown -R www-data:www-data /var/www/metrika.clickshot.ru/storage
sudo chmod 770 /var/www/metrika.clickshot.ru/storage
```

Перед запуском новой версии выполните миграцию от пользователя PHP-FPM:

```bash
cd /var/www/metrika.clickshot.ru
sudo -u www-data php bin/database.php migrate
```

Для существующей базы сначала сделайте резервную копию (путь должен быть новым):

```bash
sudo -u www-data php bin/database.php backup storage/before-upgrade.sqlite
sudo -u www-data php bin/database.php migrate
sudo -u www-data php bin/database.php audit
```

CLI использует `METRIKA_DB_PATH` из своего окружения, а не из конфигурации FPM.
Если путь нестандартный, передайте его явно. Не открывайте новую версию для трафика
до завершения миграции. Она сохраняет существующие сайты/настройки/агрегаты,
не очищает исторические данные и больше не создаёт демонстрационный сайт автоматически.
На новой установке создайте первый сайт через дашборд и используйте выданный ID.

### 5. Настроить PHP-FPM

Открыть:

```bash
sudo nano /etc/php/8.3/fpm/pool.d/www.conf
```

Добавить:

```ini
env[METRIKA_DASHBOARD_PASSWORD] = "СЮДА_ДЛИННЫЙ_ПАРОЛЬ"
env[METRIKA_TIMEZONE] = "Europe/Moscow"
env[METRIKA_DB_PATH] = "/var/www/metrika.clickshot.ru/storage/metrika.sqlite"
```

Перезапустить:

```bash
sudo systemctl restart php8.3-fpm
```

### 6. Настроить Caddy

Добавить в `/etc/caddy/Caddyfile`:

```caddyfile
metrika.clickshot.ru {
    root * /var/www/metrika.clickshot.ru/public

    @counter path /counter.js
    uri @counter replace /counter.js /api/loader.php

    php_fastcgi unix//run/php/php8.3-fpm.sock
    file_server

    @health path /health
    rewrite @health /health.php
}
```

Проверить:

```bash
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

### 7. Проверить DNS

A-запись:

```text
metrika.clickshot.ru → IP сервера
```

### 8. Проверить работу

```bash
curl -I 'https://metrika.clickshot.ru/counter.js?id=SITE_ID'
```

Должно быть `200 OK`.
Замените SITE_ID на ID созданного сайта. Без ID загрузчик возвращает 404.

Проверка API:

```bash
curl -i 'https://metrika.clickshot.ru/api/hit.php' \
  -X POST \
  -H 'Origin: https://neural-courses.ru' \
  -H 'Content-Type: application/json' \
  --data '{"site":"neural_courses","path":"/test/","referrer":"https://yandex.ru/search/","newVisit":true}'
```

Ожидается:

```text
HTTP/2 204
```

### 9. Открыть дашборд

```text
https://metrika.clickshot.ru/
```

Логин:

```text
admin
```

Пароль — значение `METRIKA_DASHBOARD_PASSWORD`.

### 10. Диагностика

```text
https://metrika.clickshot.ru/health
```

## Что собирается

- по настройке сайта: просмотры и дата/час;
- по настройке сайта: шаблон пути страницы без query-параметров;
- по настройке сайта: домен источника, без полного URL;
- при включённых источниках: безопасные рекламные метки UTM (`utm_source`, `utm_medium`, `utm_campaign`) без сквозных клик-ID;
- по настройке сайта: визиты с 30-минутным окном активности в `sessionStorage`;
- автоматический расчёт показателя отказов (Bounce Rate) на основе правила 15 секунд и вовлечённости;
- автоматический перехват клиентских переходов в SPA (`pushState`, `replaceState`, `popstate`);
- по настройке сайта: семейство браузера, ОС и тип устройства;
- экспорт полного отчёта в CSV (с поддержкой Excel).

Технические категории выключены по умолчанию. Полная строка User-Agent не
сохраняется: она сразу сводится к одной из крупных категорий. Пути с UUID,
длинными числовыми ID, токенами и e-mail маскируются как `:id`.

В админке для каждого сайта можно включить или выключить страницы, источники,
визиты и технические категории. Новые события начнут
обрабатываться по настройке сразу; уже сохранённые агрегаты не удаляются.

## Slide Cookie

ClickShot отправляет агрегаты и события баннера до согласия. Они не зависят от
разрешения Яндекс.Метрики. Новые cookie, идентификаторы посетителей и IP-логи
приложение не создаёт. При включённых визитах остаются булевы маркеры вкладки
в sessionStorage; выключение визитов отключает эти маркеры также для целей.
Согласие баннера хранится отдельно как булево значение в localStorage.
Это техническая модель, а не юридическое заключение.

В админке сайта можно включить Slide Cookie и настроить ссылку на политику,
условие показа, цвета, блокировку Яндекс.Метрики и её ID. Настройка «Запросить
согласие заново» меняет версию локального ключа согласия — баннер отобразится
повторно без хранения идентификаторов посетителя на сервере.

При включённом Slide Cookie не используйте `async` и вставьте обновлённый код
в `<head>`. Иначе баннер покажется, но не сможет гарантированно остановить
теги, которые уже успели загрузиться.

UTM-условие управляет только показом баннера. Если блокировка Метрики включена,
без согласия поддерживаемый динамический сниппет блокируется и при несовпадении UTM.
Страница без показанного баннера не получает согласие автоматически.

## Контракты и эксплуатация

- Цель не создаёт просмотр; источник цели — текущий document.referrer, как у просмотра.
- Обычный вызов Яндекс.Метрики `ym(ID, 'reachGoal', 'form_sent')` после загрузки
  ClickShot автоматически создаёт одноимённую цель ClickShot; второй вызов не нужен.
  Имена должны соответствовать формату `a-z`, цифры и `_`, от 2 до 64 символов.
  Цели, вызванные до загрузки `counter.js`, перехватить невозможно, поэтому ставьте
  ClickShot выше кода, который вызывает цели. Внутренние цели Slide Cookie не дублируются.
- «Просмотры и динамика» управляет общим счётчиком, а страницы/источники/техника — независимыми разрезами.
- Визит остаётся приблизительным признаком вкладки, без таймаута и без случайного ID.
- При false/исключении sendBeacon используется fetch; маркер не сохраняется при известном отказе отправки.
- Origin проверяется прежде Referer; без обоих заголовков hit отклоняется. Они не защищают от подделки небраузерным клиентом.
- По умолчанию принимается до 6000 событий на сайт в минуту (`METRIKA_HITS_PER_MINUTE`).
  Лимит хранит только сайт, минуту и количество, без сведений о посетителе.
  Новые значения ограничены 10000 путями, 1000 источниками и 200 именами целей на сайт в день.
  Превышение возвращает 429; существующие агрегаты не удаляются. Подберите лимит под реальный трафик.
- API читает не более 8193 байт JSON и не раскрывает сообщения SQLite в HTTP-ответах.
- `/health` возвращает 503 при проблемах с обязательными расширениями, базой или правами.
- `php bin/database.php backup NEW_PATH` создаёт проверенную копию с учётом WAL, не перезаписывая файл.
  Для восстановления остановите приём трафика и FPM, сохраните отдельно текущие sqlite/wal/shm,
  восстановите проверенную копию в настроенный путь без старых wal/shm, верните владельца и права,
  выполните миграцию нужной версии и проверьте health/статистику до открытия трафика.

Изменения схемы/бэкапы сначала проверяйте на копии. Автоматической очистки старой истории нет:
ошибочные просмотры прошлых версий нельзя точно пересчитать без исходных событий.

Полная проверка разработки: `bash tests/check.sh` (PHP 8.3+, Node 22).
Включает миграцию старой схемы, параллельные миграции, резервное копирование,
23 HTTP/JS-проверки и все 32 комбинации настроек. Сценарии запускаются на своих
временных БД; рабочий storage не используется. CI настроен на PHP 8.3.

Браузерный стенд: `node tests/browser-server.mjs`, затем открыть
`http://127.0.0.1:18743/fixture`. Для безопасного теста перехватывайте запросы
`https://mc.yandex.ru/**` тестовым ответом в Playwright; реальный счётчик не нужен.
Режим `?mode=attribute` проверяет setAttribute, `?mode=conditional` — несовпадение UTM.
При проверке 13.09.2026 в Chromium: до согласия просмотр и показ баннера получили 204,
Метрика не загрузилась; после принятия тестовый tag.js загрузился один раз.
Проверены оба способа присваивания src, другой origin, UTM mismatch и создание
нового сайта без переноса настроек предыдущего. Это не проверка production-тегов.

## Что не собирается приложением

- IP;
- cookie;
- fingerprint;
- полный User-Agent и версии браузеров/ОС;
- разрешение экрана;
- пользовательский ID;
- полный referrer URL;
- query-параметры.

## Добавление сайта

Можно через форму в дашборде.

После создания система покажет код:

```html
<script src="https://metrika.clickshot.ru/counter.js?id=SITE_ID" async></script>
```

## Важное замечание

Caddy, CDN или хостинг могут отдельно сохранять IP в access logs.
Для домена `metrika.clickshot.ru` не включайте access log.
